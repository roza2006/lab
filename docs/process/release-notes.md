## 1 定位与边界

智慧医疗在线问诊与处方流转平台，用于软件工程课程实验演示。全部数据为虚构，不接入真实医疗机构，不用于真实诊疗、开方或药品流通。

v1 **只交付四个核心上下文**：Identity、Consultation、Prescription、Circulation。药品目录、审计、通知、运营管理只保留表结构、页面骨架或设计说明，不计入本版功能。

## 2 本版包含

| 模块 | 能力 | 状态 |
|---|---|---|
| 认证 | 账号密码登录、JWT 签发与校验、角色（患者/医生/药师/管理员）、登录/消息/全局限流 | 已实现 |
| 问诊 | 创建会话、医生接诊、图文消息、结束会话、我的问诊列表 | 已实现 |

| 流转 | 患者为本人 `APPROVED` 处方选药房发起；药师/管理员也可发起；药房接方/拒接；处方 `APPROVED → CIRCULATED` 同事务 | 已实现 |

| 前端 | 患者 7 页、医生 4 页、药师 3 页、管理 4 页骨架；角色路由守卫 | 主流程已接后端；管理端为骨架 |

## 4 运行方式

### 4.1 单机演示

```bash
docker compose -f deploy/docker-compose.yml up -d --build
cd frontend
pnpm install
pnpm dev
```

后端默认 `127.0.0.1:8080`，前端 `0.0.0.0:5173`。浏览器打开 `http://localhost:5173`。

### 4.2 多机演示

一台电脑跑全部服务，其他电脑浏览器访问 `http://<主机IP>:5173`。不需要云服务器，MySQL/Redis/后端不对外暴露。完整步骤、防火墙、Tailscale 远程连接见：

- `docs/demo/local-network-test.md`

## 6 演示路径

1. 患者登录，发起问诊；
2. 医生接诊、发消息、开方、提交；
3. 药师审核通过/驳回；驳回后医生修改重提；
4. 患者选择药房发起流转；
5. 药师接方、核销；
6. 患者查看处方追踪。

前 3 步是审核闭环；第 4–6 步需要 `seed.sql` 的药房与药师档案，当前已提供。

## 7 已知限制

1. 无真实身份核验、CA 电子签名与药房资质外部校验；签名是 SHA-256 摘要。
2. 令牌存 `localStorage`，无刷新令牌、无主动吊销，未设置 CSP。
3. 限流是单机 `ConcurrentHashMap` 固定窗口，多实例不共享，重启清零。
4. 审计未写入；关键操作只能靠业务表与审核记录追溯。
5. 未开启 HTTPS；公网隧道仅可用于虚构演示数据。
6. 审核阶段不绑定药房，待审队列全平台共享；药房隔离从流转单开始。
7. 单实例 MySQL/Redis，无主从、无备份演练。
8. `docker compose up` 未在干净机器完整演练，CI 只做配置校验。
