## 1. 定位与边界

智慧医疗在线问诊与处方流转平台，用于软件工程课程实验演示。全部数据为虚构，不接入真实医疗机构，不用于真实诊疗、开方或药品流通。

## 2. 本版包含

| 模块 | 能力 | 状态 |
|---|---|---|
| 认证 | 账号密码登录、JWT 签发与校验、角色（患者/医生/药师/药房/管理员） | 已合入 |
| 问诊 | 创建会话、医生接诊、图文消息收发、结束会话、我的问诊列表 | 已合入 |
| 处方 | 创建草稿、修订、提交审核、取消、列表与详情；8 状态机（草稿/待审核/驳回/通过/流转中/已核销/已取消/已过期）与非法迁移拦截 | 已合入 |
| 审核 | 药师审核队列、通过（写签名摘要）、驳回（理由不少于 10 字）、审核记录查询 | 已合入 |
| 前端 | 患者端、医生端、药师端、管理端四套页面骨架与角色路由，开方页、审核页、核销页、处方追踪页 | 已合入 |

| 本地编排 | MySQL 8 + Redis 7 + 后端的 compose 与多阶段 Dockerfile | 已合入 |

## 4. 运行方式

后端（Java 17 + Maven 3.9）：

```bash
cd backend
mvn -B -ntp verify          # 编译并跑测试
mvn spring-boot:run         # 默认 8080，需要 MySQL 与 Redis
```

本地编排（需要 Docker）：

```bash
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml logs -f backend
docker compose -f deploy/docker-compose.yml down
```

前端（Node 20 + pnpm）：

```bash
cd frontend
pnpm install
pnpm dev
```

数据库迁移：应用启动时由 Flyway 执行 `backend/src/main/resources/db/migration`；当前 `FLYWAY_ENABLED` 默认关闭，需显式开启。仓库内迁移文件位于 `database/migrations/`，合入应用前需同步到 classpath 目录。

配置通过环境变量注入，仓库不含真实密钥：`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`、`REDIS_HOST`、`REDIS_PORT`、`SERVER_PORT`、`JWT_SECRET`（生产必须覆盖，默认值仅本地演示）。

## 5. 演示路径与当前可用性

| 步骤 | 操作 | 当前是否可演示 |
|---|---|---|
| 1 | 患者登录，同意演示说明，填写既往诊断与主诉，发起问诊 | 可用 |
| 2 | 医生登录，接诊，收发消息，填写诊断与药品，创建草稿并提交审核 | 可用 |
| 3 | 药师登录，在审核队列通过或驳回 | 可用 |
| 4 | 患者选择合作药房并发起流转 | 页面可用，接口未实现 |
| 5 | 药房接方、备药、核销，患者查看用药指导 | 页面可用，接口未实现 |

前 3 步构成当前可完整演示的闭环；第 4、5 步在 R5-A/R5-B 合入后才可用，演示时如实说明。

## 6. 演示账号

仓库当前没有种子脚本，`sys_user` 需要手工插入。插入方式与字段要求见 `database/README.md`；插入前需用 BCrypt 生成密码哈希，角色取值 `PATIENT`、`DOCTOR`、`PHARMACIST`、`PHARMACY`、`ADMIN`。

种子脚本补齐后（R5-E），演示账号将固定为虚构值并写入 `database/seed.sql`，本文件同步更新。

## 7. 已知限制

1. 无真实身份核验、电子签名与资质校验，签名仅为摘要字符串。
2. 令牌存放在浏览器 `localStorage`，存在 XSS 窃取风险；未设置 CSP。
3. 无登录失败限流、无令牌吊销。
4. 审计日志未写入，关键操作不可追溯。
5. 未开启 HTTPS，本地为 HTTP。
6. 图片消息只支持对象存储键，未开放上传，无附件类型与大小校验。
7. 单实例 MySQL/Redis，无主从、无备份演练。
8. `docker compose up` 未在真实机器完整演练，CI 仅做静态校验。

以上限制与 `docs/security/threat-model.md` 的 T-01～T-17、`docs/security/checklist.md` 的未落实项一一对应。

## 8. 升级与回滚

- 数据库：迁移文件按 V002、V003、V004 顺序执行；回滚需手工编写逆向脚本，仓库暂未提供 down 迁移。
- 代码：`git revert` 对应合并提交即可回到上一版本；文档改动可直接回退。
- 版本标签：`v1.0.0` 计划在 R6 收尾时打在当前 main 的发布提交上，标签信息包含提交哈希与日期。
