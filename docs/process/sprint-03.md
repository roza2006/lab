## 5. 偏差与问题

| 编号 | 现象 | 原因 | 影响 | 处理 |
|---|---|---|---|---|
| S3-01 | 核销用例先于实现合入，多数用例 `@Disabled` | R5-A/R5-B 后端实现未在截止前合入，测试按用例先行开发 | 容易造成"测试已覆盖"的错觉，实际执行中被跳过 | 在测试报告与答辩中明确说明；实现合入后由作者删除 `@Disabled` 并复跑 |
| S3-02 | 无 `database/seed.sql`，演示账号需手工插入 | R5-E 未完成 | 演示前必须手工建账号，换机器不可复现 | 列为 R6 阻塞项，由魏宇佳补齐；补前演示一律用同一台机器 |
| S3-03 | `docker compose up` 未在真实机器演练过 | 提交者本机无 Docker，仅 CI 做 `compose config` 静态校验 | 演示环境启动风险未知 | R6 前在装有 Docker 的机器完整跑一次并记录 |
| S3-04 | `docs/process/`、`docs/security/` 长期为空占位 | F 的 R3/R4 文档 PR 因与 main 冲突未合并，拖了 5～12 天 | 文档目录与代码进度脱节 | 已在 PR #34 按最新 main 重建提交，合并后归档 |
| S3-05 | 多人同时修改 `docs/ai-usage.md` 表格末尾 | 每轮每人都追加一行，PR 跨天即冲突 | 两次文档 PR 因此无法合并 | 文档类 PR 当天合并；补记时按日期插入对应段落而不是一律追加到末尾 |
